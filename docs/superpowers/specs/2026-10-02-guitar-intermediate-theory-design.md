- 日期：2026-10-02
- 状态：2026-10-02 已获用户书面设计批准，进入实施计划阶段
- 基线：`main`，`a7cef15`
- 关联规范：[首版知识库设计](2026-08-22-guitar-knowledge-base-design.md)

## 1. 用户目标与本轮定位

用户认为现有内容过于基础，要求多补充乐理，明确将内容置于外观之上；已选择“系统掌握中级乐理，并能用于吉他分析与演奏”。用户已确认本设计第 3 节的六个知识领域，以及第 4 节的深度、练习和验收原则。

本轮采用“深化原有章节＋补齐知识链”，不另建一套教材。目标读者已有初步吉他经验，但可能尚未系统学习乐理。入门者仍能沿原入口学习；有基础者可进入中级路线，并按真实先修知识补缺。

完成后，读者应能：

- 根据音名、音程和调性推导音阶与常见和弦，而非只背公式或指型。
- 读懂课程中的节奏与音高记法，将其对应到可复查的吉他音位和演奏。
- 分析有明确上下文的大小调和弦进行，说明功能、终止、转位及声部连接。
- 识别入门级副属、借用和弦和转调现象，说明判断依据与分析边界。
- 将原创短乐句移调、选择基本和弦与配置，并用答案解析检查自己的推理。

“中级”以这些能力和下述覆盖范围定义，不以篇数、字数、图片数量或测试数量定义。

## 2. 现状与设计取舍

现有知识库包含 75 篇正式页面，使用同一个 `content/` 目录服务 Obsidian 和 Quartz。基础乐理模块只有 8 篇；节奏、和弦和弹唱模块已有相关入门内容。主要不足是推导、跨调迁移、完整和声知识链与练习解析不足，不能仅靠追加术语解决。

已讨论的方案：

1. **原地深化并补齐知识链：采用。** 保留入口和既有页面身份，集中解释核心概念，新增相对独立的主题，再通过先修与路线连接。
2. 只追加独立文章：改动较小，但容易保留旧文章与新知识之间的断层。
3. 另建独立教材：可以独立编排，但会重复已有内容、产生两套解释与维护负担。

本轮是首版之后的内容扩充。原设计中的 60–80 篇上限和约 75 篇配额只约束首版，不限制本轮；其他未被本设计明确调整的安全、版权、单一内容源和兼容性约束继续有效。原设计作为历史记录保留，不改写成仿佛首版已经包含本轮内容。

范围边界：

- 调式、副属、借用与转调均达到能解释基础机制、辨认常见情境和完成简单应用的深度；不延伸成高级爵士或作曲专业全课程。
- 复杂扩展和弦、爵士替代和声、系统爵士即兴、完整对位法与复杂节奏体系不进入主线。
- 读谱内容服务本课程的例子和吉他应用，不另建完整视唱练耳或古典吉他教程。
- 不新增互动工具、账号、云同步、音视频制作、托管部署、前端改版或依赖升级。

## 4. 内容深度与写作标准

### 4.1 每篇核心教学页的内容契约

本轮新增和实质深化的核心教学页均须具备：

1. **明确问题与学习目标。** 说明要解决什么问题、需要哪些知识，以及学完能做什么。
2. **可追溯的推导。** 从先修知识逐步解释结论，展开关键中间步骤，说明适用条件；表格和公式用于总结，不能替代解释。
3. **完整示例与迁移。** 提供逐步解答的例子；涉及音高与和声的核心概念须包含不止一个调或根音情境，至少一个不是 C 大调。节奏主题改用不同拍号、分组或节奏情境，不机械套用“多调”要求。
4. **对比与边界。** 解释一个与本课目标相关的易混淆情境、反例或限制，不能只列“注意区分”。
5. **实际应用。** 涉及指板、和弦或和声时，明确音位、音区、实际发声音、听辨任务或编配步骤；涉及节奏时，明确拍点、时值和可执行的拍手或演奏任务。无需给纯概念页强塞复杂按法。
6. **分级练习与解析。** 覆盖辨认、推导、应用，答案具有解释而非仅列结果。
7. **自检与回退路径。** 自检针对学习目标；常见错因指向可复习的知识。下一步链接有明确用途。
8. **对应来源。** 关键结论与引用能对应；延伸阅读不能冒充已核查的论据。

不统一设置正文最低字数，不以堆砌术语、复制安全提醒、重复导航或公式表凑深度。必要安全提醒与安全入口继续保留，不能为了压缩文本删除实际操作风险边界。

### 4.2 练习与答案

- 辨认题检验概念区别；推导题要求写出过程；应用题要求分析或完成短小音乐任务。
- 每道封闭题都提供可核对的结果和关键步骤，并与题号对应。
- 开放题提供至少一种有解释的参考处理、评价标准与可能不同的合理选择；不得暗示唯一标准答案。
- 演奏或听辨任务给出检查方法和观察点；没有实际音频时不声称已完成听觉验收。
- 答案置于同页“分级练习”下独立的三级标题之后，与题目分隔；不依赖折叠脚本、插件或联网查看答案。
- 分阶段自检与综合测验链接到已教授的知识，不以尚未讲解的概念出题。

### 4.3 术语与适用语境

编写前统一音名、升降号、音区、音级、罗马数字、和弦符号、低音与吉他弦序的表达。涉及不同分析体系或习惯时，在第一次出现处说明选择，并在对应文章保持一致。

古典和声、流行编配和调式音乐中的描述要标明语境；旋律小调、级数记法、终止分类和声部连接等容易因体系不同而产生歧义的主题必须明确本课采用的约定。听感描述作为提示，不作为无条件的理论定律。

## 5. 内容组织与兼容性

### 5.1 保留身份，调整知识联系

- 保留既有正式页面的文件路径、标题、manifest ID 和 `permalink`，不因内容变深而全库重命名。需要更精确的说明时更新 description 和正文。
- 现有 8 篇乐理页面都按本轮标准审查并深化，作为知识链的基础入口；较大的新增主题独立成章，不把整个体系塞进这 8 篇。
- 节奏、常用七和弦、移调和编配等已有页面优先复用并按需要深化，避免新增同义重复文章。
- 主题的详细原理只设一个主讲位置，其他页面使用简明回顾和明确链接；正文不能变成仅有跳转的索引壳。
- 首页、学习路线、相关索引、术语表和阶段测验同步接入新内容；新增页面不能成为不可达的孤立页。

### 5.2 学习顺序与先修关系

课程由读谱／节奏基础和音高／音程基础起步，进入音阶与调性、和弦体系、功能和声，再进入综合分析与编配。两条基础线可以独立学习，在应用阶段汇合。

`prerequisites` 只表达理解当前页面确实必要的知识，不把“上一页”自动当作先修。需要衔接的教学页若存在为目录顺序设置的前置条件，应与本轮一起修正；例如学习音名不应要求先完成整首编配，学习节拍不应要求先掌握大横按。调整范围限于本轮入口与受影响的知识链，不借机重写无关演奏或保养章节。

manifest 的排列继续满足先修先出现且无循环的规则；它可以跨目录排列。下一步与相关链接可以前后互指，不混淆导航关系和必要依赖。

实施计划须在并行编写前列出逐页清单：现有页的深化内容、新页身份、所属模块、先修、主讲概念与验收点，并检查六个领域无缺项、无重复主讲。新增主题的合并或拆分依据教学边界决定，不能通过减少内容满足旧配额；既有页面仍保留身份和有效内容。

### 5.3 文件模型与数据流

继续采用：`content/` Markdown 与本地附件 → 内容／资源／来源检查 → Quartz 构建；Obsidian 直接读取同一个 `content/`。

- 不更换 Quartz，不新增知识库子系统或第二套内容源，不手写 `public/` 中的生成文件。
- 沿用现有 frontmatter 字段、页面类型和难度枚举；“中级”是课程目标，页面沿用现有“基础／进阶”等值。
- 沿用教学页八个二级栏目，通过三级标题组织推导、例题和答案。不要求未纳入本轮的旧文章全部重写模板。
- 所有课程正文和答案均可离线阅读；外部链接用于来源和补充，不承担正文中的必要解释。
- 图表只用于解释重要关系；能用文字、表格和谱例解决时不增加装饰图。必要 SVG 继续使用既有安全和无障碍约定，不扩建通用图示框架。

## 6. 清单与测试契约的最小迁移

现有 `data/content-manifest.yml` 使用 `version: 1`，其字段可继续承载本轮页面；但 `scripts/content/loadManifest.ts` 把上下限固定为 60 与 80，部分测试固定 75 页、模块配额、页面顺序或历史文件内容。这些首版范围假设需要针对性迁移，不能用跳过测试解决。

迁移设计：

1. 保留 manifest 字段结构与既有十个模块 ID，不为本轮引入新的格式版本。
2. 发布上下限继续要求正整数且下限不大于上限，取消解析器对数字 60／80 的硬编码。新版 manifest 的具体上下限与模块目标按已审核的逐页清单确定，不使用任意巨大上限放行。
3. 正式页面存在性、清单与目录的一致性、身份唯一性、草稿状态、必需栏目、来源、附件及先修图检查继续有效。
4. 首版固定总数、固定模块清单和历史正文快照等断言，仅在与批准的改动直接冲突时更新；保留并补充真实的语义检查与错误用例。不能用“断言实际值等于实际值”或批量删除旧测试替代契约迁移。
5. 对本轮理论例子增加可机械核对的测试，例如音程／和弦拼写、音区、指板音高或时值总量。用独立预期结果核对实际页面中的例子，不另造一份未经关联的“正确数据”作为装饰测试。
6. 程序可验证的事实、结构和来源记录，与逐页内容审校分别验收；关键词存在、字数达标或自动测试通过均不证明讲解充分。

本节限定的是支持内容扩充所必需的维护，不授权与内容无关的验证框架重构、样式调整或依赖更新。

## 7. 来源、谱例与纠错

- 关键理论在写作时查阅可追溯的大学教材、作者公开教材或机构教学资料；实际打开并核实支持的章节，不凭记忆拼来源链接。
- 使用原创解释、原创短练习与谱例，避免复制教材的大段表述或受版权保护的完整歌曲、歌词、曲谱。
- 每篇列出实际使用的来源及访问日期；新增来源同步进入现有参考总表与来源审计。
- 对同一术语或规则存在的体系差异说明语境；不能确认的事实先核实或删去，不以确定语气发布。
- 记录“能访问”和“支持论断”两个不同结果。在线链接检查不可替代内容核查，也不成为离线构建的必要条件。
- 内容审校发现例子或答案错误时，先修正文及相关练习、引用和测试，再复查关联页面；不得只更改测试预期让错误通过。

## 8. 验收设计

### 8.1 内容验收优先

每篇新增或实质深化的核心教学页均记录覆盖范围、推导、迁移例子、应用、练习答案与来源的审校结果。采用交叉审校：负责某批内容的编写者不作为该批唯一的正确性检查者。

对六个领域至少各选择一个完整学习任务作端到端复核，检查读者是否能只依赖已给出的正文、先修页和答案完成任务。综合应用必须有完整原创短乐句的分析与编配示例，而非只有和弦名序列或编配步骤清单。

以下情况不得判为完成：知识范围缺项；只有名词和公式而无推导；例题与答案矛盾；未讲授的概念成为隐含前提；解释依赖外部视频；重要结论无可靠依据。不能因测试已绿而接受这些缺陷。

### 8.2 自动检查与使用回归

- 执行现有 `npm run verify:release`，包含单元测试、类型／格式、发布内容、图示、来源、构建及输出检查；必要迁移仍须按第 6 节保留有效约束。
- 检查原页面稳定链接和新页面链接、先修顺序、路线可达性、索引及搜索收录。
- 对代表性的新增长文、练习答案、必要谱例和图表进行 Quartz 与 Obsidian 离线阅读检查。范围围绕本轮变化，不重新做与内容无关的视觉改版验收。
- 若设备、应用或网络使某项实机验证无法进行，报告具体未验证项，不将静态检查冒充实机结果。
- 更新内容审校记录、来源报告、使用说明中实际受影响的数量／范围说明，并在最终交付中列明新增和深化的主题、入口与剩余限制。

## 9. 执行边界与并行方式

用户要求直接在 `main` 工作，不创建分支或工作树；保留这一选择。实施阶段沿用用户偏好的子代理协作，将可独立完成的内容批次并行处理。

执行依赖如下：

1. 本书面设计经用户审核后，编写实施计划并交用户审核。
2. 实施开始时先统一逐页清单、术语约定、先修依赖和内容验收契约。
3. 各独立批次分配不重叠的正文文件；依赖前一批知识的章节以已固定的概念契约为依据，交叉引用在集成时复核。
4. manifest、公共类型、路线和索引、来源总表、公共测试与汇总报告由明确的单一负责人集成，避免并行覆盖共享文件。
5. 内容交叉审校、相关修正及整体验收结束后交付。不得自行推送或部署。

本轮开始时已有未跟踪的 `.impeccable/` 工具配置，与内容扩充无关，应保留且不混入本轮提交。旧版本已完成的验收记录作为历史保留，不复写为本轮证据。

## 10. 审核与交付边界

本文是设计规范，不代表扩充内容已经编写，也不代表本轮测试或理论审校已经通过。本次只提交设计文件；用户批准书面设计后才进入实施计划阶段，批准实施计划后才开始正文和代码变更。

最终完成标准是六个领域达到规定的教学深度，原有入口与双端使用方式保持可用，并有内容审校与技术检查两类证据。篇数仅用于说明交付清单，不作为内容质量的替代指标。
